# 中国移动云视讯（125339）Electron 桌面壳 —— 可行性分析

> 分析对象：`www.125339.com.cn`（登录）+ `conf.125339.com.cn`（门户）
> 分析方式：源码/接口实测（非纯纸面推演），并交付了一个可运行的 Electron 原型
> 分析日期：2026-11-04

---

## 0. 结论先行

| 问题 | 结论 |
| --- | --- |
| 技术上能不能做 | **能**。登录窗 + 门户窗 + 会议窗都能在 Electron 里跑通，关键环节已在原型中实测 |
| 能不能在壳子里"开会" | **能，但有一个前提**：必须走 `conf.125339.com.cn/webrtc/` 这条网页会议通道（华为 HRTC Web SDK）。若你们租户没开 `supportWebRtc`，点"加入会议"仍然只会拉起 `cloudlink://` 原生客户端 |
| 登录后能否自动进门户 | **能**。门户要一个动态 nonce 入口，`window.open` 里接住即可（已实测跑通） |
| 工作量 | MVP **2～3 人日**（登录+放大+接入口已完成）；可交付版本（自动更新、签名、异常兜底）**再加 3～5 人日** |
| 长期成本 | 站点一改版就可能坏，需预留 **0.5～1 人日/月** 维护 |
| 最大风险 | **不是技术，是合规与"套壳"的可持续性**（用户协议、商标、二次分发），以及站点改版 |
| 建议 | 原型已用真实账号跑通"登录 → 放大 → 进门户"；剩下的风险是"能不能开会"，见 §10 |

一句话：**技术上完全可行，甚至比你预期的更容易（官方网页版本来就带完整会议客户端）；真正要评估的是"值不值得自己维护一个壳"。**

## 1. 需求还原

- 现在的网页版"不够友好"：有地址栏/标签页、每次要输网址、登录态容易掉、无法开机自启、屏幕共享体验差。
- 想要一个桌面 App：**像微信 PC 端一样，先弹一个小登录框**，登录成功后自动进入门户工作台。
- 用户给定的两个地址：
  - 登录：`https://www.125339.com.cn/auth/SignIn`
  - 登录后：`https://conf.125339.com.cn/#/portal/`

## 2. 现状实测（这部分是本次分析的一手证据）

### 2.1 站点拓扑

| 域名 / 路径 | 是什么 | 技术栈 | 实测依据 |
| --- | --- | --- | --- |
| `www.125339.com.cn` | 官网 + 统一登录 + 自助服务 | Next.js + MUI(React) | `X-Powered-By: Next.js`、`_next/static` |
| `www.125339.com.cn/auth/SignIn` | **全站统一登录页** | Next.js | 页面标题"登录"，账号/密码两个输入框 |
| `conf.125339.com.cn` | 云视讯**管理门户**（会议预约/通讯录/录制） | CRA(React) SPA，`#/` 哈希路由 | `static/js/main.*.chunk.js`，158 个懒加载 chunk |
| `conf.125339.com.cn/#/login` | 门户自带的登录路由 | 同上 | 实测：**会跳转到 `www/auth/SignIn`** |
| `conf.125339.com.cn/webrtc/` | **真正的网页版会议客户端** | React + 华为 HRTC Web SDK | 页面标题"我的会议"，控制台有 `[HRTC]` 日志 |
| `meeting.125339.com.cn` | 另一个"云视讯"Web 应用（带阿里播放器） | CRA | `config.js` 里 `login` 指向 www 的 SignIn |
| `conf.125339.com.cn/v1/usg/*`、`/v1/mmc/*` | 华为 CloudLink 后端接口 | nginx 反向代理 | 前端硬编码 `SSO:"/v1/usg/acs"`、`CMS:"/v1/mmc"` |

**关键发现 1：登录页只有一个，就是你要的 `www/auth/SignIn`。**
在 Electron 里打开 `conf/#/login`，页面自己 302 到了 `www/auth/SignIn`（实测最终 URL 就是 www 那个地址）。所以"登录地址"和"门户地址"分属两个子域，这是官方设计，不是你的理解有误。

**关键发现 2：门户里没有 WebRTC，会议界面是独立的一页。**
我把门户 158 个 chunk 全下载后扫描：`getUserMedia` / `getDisplayMedia` / `RTCPeerConnection` 出现次数 **全部为 0**。真正的音视频在 `/webrtc/` 这个独立应用里（华为云会议 Web 客户端），它的 SDK 里有 162 处 `RTCPeerConnection`、7 处 `getDisplayMedia`。

这意味着：

> **只套门户 ≠ 能开会。** 必须把"门户"和"网页会议"两条路径都接进壳里，否则用户点"加入会议"只会被丢回原生客户端。

### 2.2 门户里的"加入会议"到底走哪条路

门户代码里有这个分支（我抓到的原文）：

```js
// conf 门户：分享链接 → 拼出网页会议地址
u = `${origin}/webrtc/?lang=${lang}&customer=${customer}`
  + `#/joinNow?confId=${confId}&enterCode=${rand}&name=${name}`
  + `&openMic=${openMic}&openCamera=${openCamera}&portal_join=ture`
```

同时门户里还有一个 **`supportWebRtc`（租户级开关）** 的 Redux selector，用来决定"网页入会"这个 Tab 是否显示。也就是说：

- 租户开了 `supportWebRtc` → 门户提供"网页入会"，壳子可以全程接管；
- 没开 → 只能 `cloudlink://welinksoftclient/h5page?page=launch` 拉起 `云视讯` 原生客户端。

**这是本项目可行性的唯一硬门槛，只有你的账号能验证（见 §10）。**

### 2.3 网页会议客户端本身（实测截图）

Electron 33 里加载 `https://conf.125339.com.cn/webrtc/`，正常渲染出会议号入会面板（`screenshots/03-webrtc-join.png`）：

```
┌────────────────────────────┐
│  ▣ 华为云会议               │
│                            │
│      请输入会议信息          │
│   ID  [ 请输入您的会议ID ]   │
│   👤  [ 请输入您的姓名   ]   │
│   [      加入会议      ]    │
│  ☑ 我已阅读并同意《服务协议》 │
│         欢迎使用华为云会议    │
└────────────────────────────┘
```

两个重要结论：

1. **入会这条路不要求登录**（下面单独展开，见 2.4）。所以桌面壳可以顺手做一个"输入会议号直接开会"的入口。
2. 页面文案里出现的是"**华为云会议**"，不是"中国移动云视讯"。这是华为 CloudLink 的白牌 OEM（详见 2.6），你在壳里会看到少量华为品牌露出。

### 2.4 「只凭会议号」到底能不能进会（实测）

我把「填入会议号 + 姓名 → 勾选协议 → 点加入」整条链路跑了一遍（会议号用的是不存在的号码）：

| 观察点 | 结果 |
| --- | --- |
| 前端提交调用的接口 | `GET /v1/mmc/management/conferences/authConf?conferenceID=...` |
| 该接口是否要求身份 | **不要求**。不带任何 Cookie/Token 直接请求，返回的是业务错误码 `{"error_code":"MMC.111072065"}`，**不是 401/403，也没有跳登录页** |
| 提交后的页面走向 | 进入"请输入密码"页（`screenshots/04-join-password.png`），说明流程本身支持匿名入会 |
| 换 4 个不存在的会议号 | 全部返回同一个错误码，说明这是"会议不存在/无法入会"的通用错误，而非鉴权失败 |

**因此准确的结论是：**

- 「加入会议」入口**在架构上就是免登录的**（访客/匿名入会），桌面壳可以不登录直接做会议号入会；
- 但**最终能不能进会，还取决于会议本身的 3 个设置**，跟登录无关：
  1. 主持人/租户是否允许**匿名（访客）入会**；
  2. 会议是否设置了**入会密码**（实测流程会弹密码框）；
  3. 是否需要**滑块/短信验证**（代码里有 `slideverifycode`、`getSmsCode` 两条验证链路）。
- 我手上没有真实会议号，所以只能验证到"发起鉴权请求"这一步，**"真的进到会议室里"还差你自己用一场真实会议点一下**。

**注意区分两条路径：**

| 路径 | 是否需要登录 |
| --- | --- |
| `conf.125339.com.cn/webrtc/`（加入会议） | ❌ 不需要（实测） |
| `conf.125339.com.cn/#/portal/`（门户：预约/通讯录/录制管理） | ✅ 需要（未登录实测被踢回登录页） |

也就是说：**"整个 App 不要登录"做不到，除非你只要「开会」不要「管理」。**

### 2.5 登录态怎么走（真实账号实测，结论推翻了最初的三条猜测）

以下结论全部来自**用真实账号在 Electron 里登录一次**的实测，不是推测。

| 观察点 | 实测结果 |
| --- | --- |
| 登录成功 | `localStorage` 写入 `Authorization`（625 字符 JWT，10 小时有效）、`contactToken`、`mobile`、`roles` |
| Cookie | **只有一个 `Authorization`，域是 `www.125339.com.cn`，hostOnly = true** —— 不会发给 conf 子域 |
| 直接访问 `conf/#/portal/` | ❌ 跳 `#/logout`，显示"登录已过期" |
| 把 www 的 token 注入 conf 的 localStorage | ❌ 仍然过期（门户要的是它自己的 token 包装，不是 www 的） |
| `GET /server/portal/token` + `Authorization: Bearer <token>` | ✅ 200，返回一个 32 位票据 |
| 带 `?ticket=<票据>` 访问门户 | ❌ 仍被弹回登录页（票据不是这么用的） |

**所以："登录成功后直接用门户地址"是不成立的。** 这也是我最初建议里最大的一个误判，已在这里更正。

**关键发现 3：真正的入口是一个动态生成的 URL。**

鼠标点「会议服务 → 移动会议」（见 `screenshots/04-menu-dropdown.png`），页面会 `window.open` 出：

```
https://conf.125339.com.cn/?lang=zh-CN&customer=chinamobile
  &nonce=1793759859038lQuhjNevXRHzGj2embzY1MnxRrq1nR34F
  &redirect=user_conference_list#/login
```

`nonce` 是**服务端发的**，不是页面瞎编的。逆向官网 `_app` 后拿到它的原始逻辑：

```js
var tt = function (e, t, n) {
  Te.Mb.get("/mobile/nonce", { params: t }).then(function (t) {
    if (t.data) {
      var r = e.replace("{}", t.data);   // e 是菜单接口给的"带 {} 占位"的地址模板
      window.open(r);
    }
  });
};
```

也就是说：**菜单接口给模板（含 `{}`）+ `/server/mobile/nonce` 给 nonce + 字符串替换 = 最终地址**。
两步都只要一个 token，所以登录成功后可以立刻算出来，**不用等工作台渲染、不用点菜单**。

**落地做法**：模板写死成常量，登录成功只取 nonce 替换 `{}`（`[resolve] ok (via template)` 已实测）；
取不到 nonce 时再退回"从菜单接口里找模板"，最后才是"截 window.open"。

三种做法都成立：

- **首选（直接算）**：登录后立刻用 token 调上面两个接口，拼出地址直接 `loadURL`；
- **兜底（接住）**：Electron 的 `webContents.setWindowOpenHandler` 正好在 `window.open` 的出口，能拿到完整 URL：

```js
contents.setWindowOpenHandler(({ url }) => {
  if (url.startsWith('https://conf.125339.com.cn')) {
    win.loadURL(url);           // 同一个窗口打开（此时窗口已放大好）
    return { action: 'deny' };  // 不要再开一个新窗
  }
  ...
});
```

这条"接住"路径**已实测跑通**：拿到 nonce 地址后用同一个窗口加载，直接落到
`conf.125339.com.cn/#/portal/cmp/user/conference/conference-list`，门户完整可用（`screenshots/03-portal-authenticated.png`）。

### 2.6 这套东西到底是谁的产品

- `cloudlink://welinksoftclient/h5page?page=launch` —— CloudLink 是**华为**的会议客户端协议；
- CSP：`connect-src 'self' *.huaweicloud.com wss://*.huaweicloud.com *.obs.cn-north-4.myhuaweicloud.com`；
- 接口路径 `/v1/usg/acs`、`/v1/mmc`、`/v1/usg/scs` 与华为云会议一致；
- 网页会议页直接写"华为云会议"、"欢迎使用华为云会议"。

结论：**中国移动云视讯 = 华为 CloudLink 的白牌 OEM**。这带来两个直接影响：

1. 站点结构、鉴权、UI 都是华为体系，改版节奏由华为/移动共同决定，**版本迁移风险偏大**；
2. 网页会议客户端里本来就带 Electron 适配代码（见 §4 R3），说明**厂商自己就是用 Electron 做桌面的**——这对我们是利好，不是坏消息。

## 3. 能力边界：壳子能做到什么、做不到什么

| 能力 | 结论 | 说明 |
| --- | --- | --- |
| 小窗登录（像微信） | ✅ | 已实现，420×560 无边框边框视感登录窗 |
| 免地址栏 / 免标签页 | ✅ | Electron 天然 |
| 记住密码 / 免登录 | ✅ | `persist:` 分区，登录态落盘；密码用 `safeStorage` 加密后可做自动填充 |
| 开机自启 / 托盘 / 单实例 | ✅ | 常规能力 |
| 门户全部功能（预约、通讯录、录制管理） | ✅ | 直接复用网页 |
| 网页入会（音视频） | ✅ **有条件** | 需租户开启 `supportWebRtc` |
| 屏幕共享 | ✅ | 需 `setDisplayMediaRequestHandler`（已实现） |
| 摄像头/麦克风权限 | ✅ | 需 `setPermissionRequestHandler`（已实现） |
| 深色模式 | ✅ | 站点未适配，壳子注入滤镜式深色（托盘可开关），见 README |
| 会议号快速入会（免登录） | ✅ 入口可用，能否进会看会议设置 | 实测：入会接口不需要身份；但受"是否允许匿名入会/是否有密码/是否要滑块验证"影响（§2.4） |
| 任务栏缩略图、会议中"静音"快捷控制 | ⚠️ 半 | 需与页面元素联动，属加工项 |
| 虚拟背景/美颜、硬件编解码优化、云录制本地录制 | ❌ 大概率不行 | 这些是原生客户端能力；网页版能用的以 `supportWebRtc` 提供的为准 |
| 替代原生客户端的全部功能 | ❌ | 定位应是"轻量开会 + 门户管理"，不是全功能替代 |

## 5. 推荐架构

### 5.1 窗口模型

```
启动
 └─ 登录窗（420×560，www/auth/SignIn）
        │ 轮询 localStorage.Authorization
        └─ 拿到 token ──► 同一个窗口原地放大到 1280×820（停在 www 工作台）
                              │
                              ├─ 自动点「会议服务 → 移动会议」
                              │      └─ 截住 window.open 的 nonce 地址
                              │             └─ 同窗加载 → 门户（带登录态）
                              └─ 点不到就让用户自己点，同样会被截住
```
窗口全程只有一个，尺寸只在 420×560 ↔ 1280×820 之间切换。

**一个窗口走到底**比"登录窗一个新窗口、会议再一个新窗口"更省事：不需要处理窗口间焦点、Cookie 分区、`window.open` 被拦等一堆问题。

### 5.2 目录结构（原型已按此实现）

```
125339/
├── package.json
├── electron/
│   ├── main.js        # 主进程：窗口、权限、屏幕共享、外链、单实例
│   └── preload.js     # 唯一职责：文档开始前注入登录态（跨源兜底）
├── screenshots/       # 实测截图
└── docs/可行性分析.md
```

### 5.3 三个必须写对的地方

**① 权限放行（否则点"开摄像头"没反应）**

```js
ses.setPermissionRequestHandler((wc, permission, cb, details) =>
  cb(isInternal(details.requestingUrl) && ALLOW.has(permission)));
```

**② 屏幕共享（Electron 不会自带选择器）**

```js
ses.setDisplayMediaRequestHandler(async (req, cb) => {
  const sources = await desktopCapturer.getSources({ types: ['screen', 'window'] });
  cb({ video: sources[0], audio: process.platform === 'win32' ? 'loopback' : undefined });
}, { useSystemPicker: process.platform === 'darwin' });
```

注意：**不要注入 `window.hwCloudMeeting`**。页面里有一段逻辑——只要检测到 `window.hwCloudMeeting.platform` 是 `uospc`/`kos`，就会劫持 `navigator.mediaDevices.getDisplayMedia` 去调厂家的私有接口；我们不提供这个对象，它就走浏览器原生路径，正好被 Electron 接管。

**③ 接住动态入口（本项目最关键的一处）**

登录态跨不过去（见 §2.5），但入口 URL 会在 `window.open` 里出现，接住即可：

```js
if (url.startsWith(CONF_ORIGIN)) {
  portalEntryUrl = url;
  if (phase !== 'main') await growToMain();  // 先把窗口放大
  win.loadURL(url);                          // 同窗加载，门户即登录态
  return { action: 'deny' };
}
```

**不要做**：伪造 nonce、破解滑块、把 www 的 token 硬塞进 conf。这三条要么不可靠，要么是绕过风控。

如果想让用户少点一次，可以让壳子代点菜单（本项目已实现，用 `sendInputEvent` 发真实鼠标事件点「会议服务」→「移动会议」）；点不到也不影响——用户自己点，一样会被接住。

## 8. 合规与风险（这部分请务必看完）

1. **套壳第三方产品本身没有法律禁止**，但要注意：
   - 你是否**有权二次分发**：如果只是自己/团队内部用，风险很低；若要对外发布，会涉及商标（中国移动/云视讯）、UI 著作权、白牌 OEM 的授权链。
   - 站点的《服务协议》《隐私声明》可能禁止"以非官方客户端方式访问"，发布前建议读一遍。
2. **不要做任何鉴权绕过**：本方案全程是"用户自己输入账号密码、在官方页面里登录"，token 只在本地会话里转存，不抓包、不破解、不代理账号体系。这条红线守住，性质就还是"浏览器外壳"。
3. **账号密码不要落盘**：如果要做"记住密码"，用 Electron `safeStorage`（走系统钥匙串）加密，绝不明文存。
4. **企业数据**：登录页上那行"严禁上传、传输、存储、处理带有'绝密'…涉密文件"是实打实的等保要求。自研壳如果有本地缓存/日志/崩溃上报，可能把会议内容带出边界，**日志和上报默认要关**。
5. **品牌**：壳子里的图标、名称别用"中国移动"官方标识去做对外发布，内部使用问题不大。

## 9. 方案对比

| 方案 | 成本 | 优点 | 缺点 | 建议 |
| --- | --- | --- | --- | --- |
| **Electron 壳（本方案）** | 3～5 人日 | 跨源登录可桥接、权限/屏幕共享可控、跨平台、可做会议号直入 | 90MB 包、需长期维护 | **推荐** |
| PWA（Chrome/Edge"安装为应用"） | 0.5 小时 | 零成本、自动更新 | 登录跳 www 后回不到门户（跨源），无跨源桥接能力；无托盘快捷键 | **先试这个做基线**，能忍就用它 |
| WebView2 套壳 | 1～2 人日 | 包只有几 MB、Win 自带运行时 | 仅 Windows、屏幕共享/多屏选择更麻烦、跨源桥接同样要自己做 | 只做 Windows 且在意体积时 |
| Tauri | 3～4 人日 | 包小、内存低 | 各平台内核不一（WebView2/WKWebView/WebKitGTK），会议音视频兼容性是抽奖 | 不推荐用于音视频 |
| 直接用官方 `云视讯` 客户端 | 0 | 功能最全 | 你觉得"不友好"的正是它 | 需求若是"开会"，它才是正解 |

**一个诚实的判断**：如果你的真实诉求是"**开会更方便**"，官方原生客户端 + 网页会议其实已经覆盖了；Electron 壳的独特价值在于 **"管理门户 + 会议号直入 + 小窗登录 + 托盘常驻" 这套桌面级收纳体验**，以及**统一入口**。如果只是"不想敲网址"，PWA 就够了；如果是要"一个像微信一样常驻桌面的工作入口"，那这个壳值得做。

## 10. 下一步

**① 确认租户是否开通网页入会（决定项目死活）**

在门户里建一场会并点"加入"，看是进会议界面还是拉起 `cloudlink://`：
- 进会议界面 → 壳子可以做到"开会"，继续；
- 只拉起原生客户端 → 壳子只能做到"管理 + 入会入口"，要么砍需求，要么去申请开通。

**② 确认使用范围与目标系统**

- 只在你自己机器 / 团队内部 / 对外发布？（决定要不要买签名证书、要不要做更新服务）
- 有没有 Windows 7？（决定 Electron 版本：22 还是 33）

**③ 要不要做"免登录存密码"**

现在每次启动都要重新登录（Cookie 是 hostOnly，会话不持久）。可以加"记住密码"：用 `safeStorage`（走系统钥匙串）加密存储，启动时自动填充，滑块仍然由你拖一次——**滑块不能也不应该自动化**。
